# 方案 A · 双侧栏资料工作台（previews/01-master-detail）

基线 c7878b6 上的独立交互原型。双击 `index.html` 即可用（file://，无构建、无 CDN、无外部依赖）。
数据为真实站点数据的副本 `links-data.js`（内容与 `data/links.js` 完全一致，未编造条目）；品牌资产复制在 `assets/`。

## 一、信息架构：与首页版的本质区别

正式首页是「分类卡片 → 分类页 → 详情页」的**页面跳转**模型：每看一条资料都要离开列表、再返回，比较两条资料需要两次往返。

本方案改成**常驻三栏工作台**，查看路径从「跳转」变成「原地切换」：

```
┌────────────┬──────────────┬────────────────────┐
│ 左栏 264px  │ 中栏 ~400px   │ 右栏 自适应         │
│ 分类导航    │ 结果列表      │ 当前资料详情        │
│ + 当前目录  │ (搜索/过滤)   │ (下载/外链/步进器)  │
└────────────┴──────────────┴────────────────────┘
```

- **左栏**＝分类（全部 + 6 类，含条数）＋「目录 OUTLINE」：当前结果集的编号清单，选中合集时展开其资料包子项（可直接下载）。分类回答「去哪找」，目录回答「这一类里有什么、我看到哪了」。
- **中栏**＝结果列表：标题、两行摘要、标签、日期、类型（zip / 网页版 / N 个资料包）。搜索与分类过滤都作用在这里。
- **右栏**＝详情：说明、来源/更新等元信息、资料包下载列表、主链接与相关入口（购买等）、复制本页链接；顶部有「上一条 / n / N / 下一条 / 关闭」。

三栏共享同一状态 `{分类, 搜索词, 选中条目}`，任何一处操作都同步另外两处；地址栏 hash（`#/c/<分类>`、`#/i/<id>`）用 `history.replaceState` 做快照，可复制直达链接，也响应手动改 hash / 前进后退。

## 二、核心交互逻辑

| 操作 | 行为 |
| --- | --- |
| 点分类 | 中栏换成该分类结果，左栏目录同步，右栏回到占位态（不保留旧详情，避免误导） |
| 搜索（顶栏，`/` 聚焦） | 在当前分类范围内匹配名称/说明/来源/标签/**资料包名与说明**，命中高亮 `<mark>`；原选中项若不再匹配则自动取消选中 |
| 点列表条目 / 目录项 | 右栏原地换详情，**列表不重建、滚动位置不动**（轻量更新只改选中态），适合逐条比较 |
| 键盘 `↑` `↓` | 焦点在列表时移动即切换详情（焦点跟随卡片）；焦点在别处时直接步进条目；`Home`/`End` 跳首尾；搜索框内 `↓` 进列表、`Enter` 选第一条 |
| 上一条/下一条按钮 | 与 `↑↓` 同一结果集顺序，两端自动禁用，位置指示 `n / N` |
| `Esc` | 分层退出：先关抽屉 → 再清搜索 → 再关详情；关详情后焦点归还触发它的列表卡片 |
| 关闭详情（×） | 取消选中，右栏回占位态，焦点归还卡片 |
| 空分类 / 无结果 | 中栏给原因 + 行动按钮（「查看全部资料」/「清除搜索」），右栏给对应占位说明，不留死区 |
| 外链 | 全部 `target=_blank rel=noopener`；GitHub Release 下载、淘宝购买原样保留；`tools/*.html` 相对链接解析为 `../../tools/…` 指回仓库内真实工具页 |

**默认状态**：桌面打开即「全部资料 + 自动选中第一条」，三栏都有内容、无需阅读说明即可上手；手机打开是纯列表页（不自动弹详情），点条目才进入详情层。

### 手机端（≤900px）：分层页面 + 抽屉，不硬挤三栏

- 列表页为主页面；顶栏汉堡按钮打开**左侧目录抽屉**（`role=dialog` + `aria-modal`，遮罩点击/Esc/关闭钮均可退出，Tab 在抽屉内循环，底层 `inert`）。
- 点条目 → **全屏详情层**滑入，顶栏变「← 返回列表」，保留上一条/下一条便于连续比较；底层列表 `inert` + 延迟隐藏，滚动互不冲突（各层独立滚动容器，`overscroll-behavior: contain`）。
- 抽屉里选分类 → 自动收起回列表页；焦点交给列表标题。
- 手机不显示桌面快捷键提示条；搜索输入 16px 防 iOS 聚焦缩放。

## 三、排版思路

- 沿用协会视觉基因（暖纸底 `#f3eee3`、墨黑、协会红 `#b02a22`、等宽小标签、`电创导航` 四字专用字体），但布局语言完全不同：首页是「纸张上的索引卡」，这里是「固定视口的工程工作台」——页面本身不滚动，三栏各自滚，右栏铺浅工程网格衬底，详情是一张带黑红顶线的资料卡。
- 左栏窄而密（分类 40px 行高、目录 34px），中栏卡片留白适中保证摘要可读，右栏最宽给下载列表；1180px 以下收窄左中栏，900px 以下转分层。
- 选中态统一用「左侧红竖线 + 红描边」，分类/目录/列表三处一致，扫一眼就知道当前在哪。

## 四、典型操作路径

1. **找试卷下载**：左栏「课业传承」→ 中栏唯一条目 → 右栏 4 个资料包按学期排列 → 点「大一上期末」直接下载；或左栏目录展开的子项直接下载。
2. **比较两个引脚规划器**：搜索「规划」→ `↓` `↓` 键盘连切两条，右栏详情原地刷新、列表不动 → 看中意哪个点「打开工具」。
3. **查调试器资料并买一块**：左栏「器件手册」→ 点条目 → 右栏下载 zip + 「购买链接」跳淘宝。
4. **手机**：汉堡 → 选分类 → 点条目 → 全屏详情 → 「下一条」接着看 → 「返回列表」回到原位置（焦点也回到原卡片）。

## 五、取舍与简化（及原因）

- **去掉首页 hero/统计大卡/最近加入**：工作台首屏寸土寸金，统计压缩成顶栏三个数字；「最近加入」与按 updated 排序的结果列表重复。
- **分类页不再是独立页面**：分类只是左栏的一个过滤态，这是本方案与首页版最大的路径差异。
- **详情不做独立路由页**：右栏常驻。hash 仍可直达（`#/i/<id>`），但用 replaceState 写快照而非 pushState——原型阶段避免历史栈被每次点选灌满；代价是浏览器后退不能逐条回退点选历史（实测后退仍可回到进入原型前的页面/手动导航的上一状态）。
- **手机详情层不保留底部列表露出**：360px 下露出列表只会造成误触与滚动冲突，选择全屏层 + 明确返回钮。
- **步进器在手机上保留**：连续比较是本方案卖点，手机上同样值得保留；桌面 × 与手机「返回列表」语义合一，手机上隐藏 ×，避免两个重复关闭钮。
- **搜索范围跟随当前分类**（与正式站一致），不做「搜索时强制回全部」——左栏随时可切回「全部资料」，路径更短。
- **复制链接**在 file:// 下走 `execCommand` 降级，失败时按钮明示「复制失败，请手动复制地址栏」，不静默。
- 未做：收藏/对比并排视图、深色模式、条目编辑——超出原型范围。

## 六、实测记录（真机浏览器，非静态检查）

环境：本机 Chromium（ms-playwright chromium-1254，headless=new）经 CDP 驱动，`file:///D:/资料/…/previews/01-master-detail/index.html` 直接打开；脚本 `verify.mjs`（Node 24 内置 WebSocket，无第三方依赖），结果存 `verify-results.json`。

**78 项断言全部通过**，覆盖：

- 桌面 1440×1000：加载渲染 4 条真实条目；默认选中第一条且详情正确；分类 7 项、目录同步；三栏独立滚动；`scrollWidth==clientWidth` 无横向溢出（默认/无结果/搜索态均测）。
- 分类→搜索→切换链路：空分类空态与恢复按钮；docs 分类过滤；搜索「引脚」命中 2 条、高亮、role=status；搜索后失配自动取消选中；`↓` 进列表、再 `↓` 切第二条且详情/焦点跟随；Esc 清搜索；无结果空态；连续点选 4 条详情逐一联动且列表容器不重建；上一条/下一条按钮；目录点选与合集子包展开；Esc/× 关闭详情并归还焦点；`/` 聚焦搜索；hash 直达跨分类同步左栏；history.back；复制链接反馈。
- 手机 360×800：默认列表页、详情层 hidden+inert；抽屉 dialog/aria-modal、焦点入抽屉、底层 inert、Tab 循环、Esc/遮罩/关闭钮三种退出且焦点归还汉堡钮；抽屉选分类自动收起；点条目开全屏详情、焦点入标题、内部可滚动、下一条切换、返回列表焦点归还原卡片；Esc 关详情；搜索「试卷」命中合集子包字段；各态无横向溢出。
- `prefers-reduced-motion: reduce`：过渡时长趋零（1e-06s）且功能正常。
- 品牌 logo 加载成功、`DC Title` 字体可用、全程无页面 JS 错误。
- 外链核对：资料包/主下载指向真实 GitHub Release 地址，购买链接指向淘宝，工具相对链接解析到仓库 `tools/` 真实文件。

开发中实际修掉的问题（如实记录）：
1. 自写 hash 的异步 hashchange 回灌会把刚关闭的详情重新打开 → 改用 replaceState 写快照，根治。
2. 关闭详情归还焦点时触发 focusin「Tab 联动」又把详情打开 → 程序化聚焦期间抑制联动。
3. 鼠标 mousedown 的 focusin 抢先切选中态，导致随后 Esc 误判 → 指针按住期间抑制 focusin 联动。
4. `hidden` 属性被 `display:flex` 覆盖出现空搜索状态条 → 补 `[hidden]{display:none}`。
5. 手机层滑入动画期间 visibility 未生效导致聚焦失败 → 焦点移交延迟到过渡结束。

## 七、已知不足

- **数据量小**（4 条目/6 分类，3 个空分类）：长列表虚拟滚动、目录折叠分组等未验证；空分类占比高是数据现状，不是设计缺陷，但视觉上左栏偏空。
- **replaceState 快照**不进历史栈：点选条目不能用浏览器后退逐条回退（见取舍）；若转正需改 pushState + popstate 全套。
- **手机详情层打开时锁底层**：无法边看详情边扫列表，这是分层方案的固有代价，靠步进器弥补。
- **搜索为子串匹配**：无拼音/模糊/分词，与正式站一致；「技本」这类缩写依赖数据里写了才能命中。
- **仅在本机 Chromium 实测**：Safari/Firefox 的 `inert`、`:focus-visible`、dvh 行为未逐一验证（均为现代浏览器 baseline 特性，风险低）。
- 复制链接在部分浏览器 file:// 下可能降级失败，已有明示文案兜底。
- 右栏详情超长时（未来条目多了）依赖栏内滚动，未做锚点目录。
